# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Jolly Web App is a multiplayer score tracker (lobbies, live game updates, game history). Two independent npm projects live side by side — `frontend/` (React 19 + TypeScript + Vite) and `backend/` (Node.js + Express 5 + MongoDB/Mongoose, CommonJS) — each with its own `package.json`. Run npm commands from inside the respective directory.

## Commands

Frontend (`frontend/`):

```bash
npm run dev              # Vite dev server on http://localhost:5173
npm run build            # production build
npm run lint             # ESLint
npm run storybook        # Storybook on port 6006
npx vitest --project=storybook   # run story-based tests (headless Chromium via Playwright)
```

There are no unit tests beyond Storybook stories; Vitest is configured only through `@storybook/addon-vitest` in `vite.config.ts`.

Backend (`backend/`):

```bash
npm start                # node server.js on port 3501 (run `npm ci` first)
```

Requires `MONGODB_URI`, `SESSION_SECRET`, `NODE_ENV`. No test or lint setup exists for the backend.

Docker:

```bash
docker compose up --build                            # full stack: frontend (3500), backend (3501), MongoDB (27017), mongo-express (8081)
docker compose -f docker-compose.dev.yml up --build  # backend + MongoDB + mongo-express only; run the frontend locally with Vite
```

## Backend architecture

Originally generated by Swagger Codegen (`api/openapi.yaml`), now hand-maintained Express. Request flow is layered:

1. `routes/*.routes.js` — mounted in `routes/index.js` at `/users`, `/api/lobbies`, `/api/games`, `/admin`.
2. `controllers/default.controller.js` — a single controller for all routes. Passes `req.user` to the service and writes responses via `utils/writer.js`. `sendError` hides messages of 5xx errors from clients.

`middleware/auth.js` provides `requireAuth()`, which every router except `/users` applies. It resolves the session (the `sessionId` cookie, or the `x-session-id` header; SSE may also use `?sessionId=`) into `req.user`. Routers also use `validateObjectId` via `router.param` to reject malformed ids. **Never trust user ids from the request body**: always use `req.user.id`. Game mutations go through `getGameForPlayer` in `DefaultService`, which requires the caller to be a non-temporary player of that game.
3. `service/DefaultService.js` — facade that validates input and delegates to `UsersService`, `LobbiesService`, `GamesService`. Errors are thrown as plain `{ status, message }` objects, and the controller uses `e.status` as the HTTP code.
4. `models/` — Mongoose schemas (`User`, `Lobby`, `Game`, `Session`).

Adding an endpoint therefore usually touches route, controller, `DefaultService`, and the domain service.

Key details:
- **Sessions** are stored in MongoDB (`Session` model, TTL-expired, the token stored as a SHA-256 hash) and survive restarts. Login is hybrid: username+password, password-less `fullTag` (`Name#1234`), or bare username, which creates a new account with a random 4-digit discriminator.
- **Real-time updates use Server-Sent Events**: `service/EventService.js` is a singleton holding SSE clients per gameId, with heartbeats and stale-connection cleanup. `GamesService` calls `EventService.sendEvent(gameId, { type, ... })` after mutations (`SCORE_SUBMITTED`, `ROUND_STARTED`, `GAME_ENDED`, `PLAYER_JOINED`, etc.). Clients subscribe at `GET /api/games/:gameId/events`.
- `mongoose.set('sanitizeFilter', true)` is enabled globally, so intentional query operators must be wrapped in `mongoose.trusted({ $ne: ... })`.
- CORS is open in `NODE_ENV=development`, and otherwise restricted to the `allowedOrigins` list in `server.js`. Port 3501 is hardcoded there.
- Game constants (points goal 1000, max 8 players) live in `config/index.js`.

## Frontend architecture

- **Routing**: TanStack Router with file-based routes in `src/routes/`. `src/routeTree.gen.ts` is generated by the Vite plugin, so don't edit it by hand. Route files are thin and render page components from `src/presentation/pages/`.
- **Data layer**: `src/core/api/client.ts` (`ApiClient`, static fetch wrapper with `credentials: 'include'` plus an `x-session-id` header) and `src/core/api/hooks.ts` (TanStack Query hooks with `queryKeys`). Mutations invalidate or set the `['game', gameId]` / `['lobbies']` queries. `useGameEvents(gameId)` opens the SSE `EventSource` and keeps the game query in sync.
- API base URL: `VITE_API_BASE_URL`, else `http://localhost:3501` on localhost, else the production API.
- `src/presentation/` holds `components/` (shared UI, some with Storybook stories), `layout/`, and `pages/` (page-specific subcomponents live under e.g. `pages/GamePage/components/`). Shared types are in `src/types/` and re-exported from `@/types`.
- Path alias `@/*` → `src/*`. Styling is Tailwind CSS v4 (via `@tailwindcss/vite`), with `class-variance-authority` + `tailwind-merge` for variants. TypeScript is strict, with `noUnusedLocals`/`noUnusedParameters` and `verbatimModuleSyntax`, so use `import type` for type-only imports.
